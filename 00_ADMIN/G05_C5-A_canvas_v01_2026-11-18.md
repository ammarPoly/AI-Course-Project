| 2 | **The problem in one sentence** | Brightkeel's category director can't tell which suppliers are a single point of failure, which contracts leave the company exposed and which suppliers were never assessed, because the evidence is spread across a master list, an assessment log and 24 memos written by different buyers over two years. |
| 3 | **What goes in** | `SUPPLIER_MASTER.csv` is the source of truth for which suppliers are approved and their part families. `ASSESSMENT_LOG.csv` is the only source for whether a supplier was assessed. The 24 memos are the only source for indemnity positions and for a supplier losing qualification. `RISK_RULES_RR-C5` (as of 2026-10-31) decides every flag and status. Nothing else counts. |
| 4 | **What comes out** | Three tables on one web page, each exportable as CSV to `OUTPUTS/`: (1) a coverage table for all 26 suppliers (memo IDs or NO MEMO, log row yes/no), kept apart from risk; (2) a scorecard with one row per master supplier showing each flag, its evidence and the status; (3) a coverage record listing every memo and data row the run read. A stranger can click any flag and see the exact memo sentence or file row it rests on, then check it in the original file. |
| 5 | What kind of system this is | A rules tool with an extraction step. Rules tools go wrong when a rule is coded slightly differently from the rule card (for example the order of the name-matching steps). Extraction goes wrong when a memo is skipped, a sentence is paraphrased instead of quoted, or a statement is attached to the wrong supplier. |
| 6 | **How we will build it** | **Form:** one self-contained HTML file (`02_WORK/control_tower.html`) that opens in any browser with no internet, no install, no server and no API key. It uses no online libraries. **Step A, page (code):** the user loads the master, the log and the memo files with a file picker. The page reads each memo's header (ID, date, supplier as written) and applies RR-C5 §2 matching step by step; any name that doesn't match exactly becomes CANNOT DETERMINE (match). **Step B, Claude (each member in their own account):** Claude reads the memos in batches of 8 (`MEMOS_BATCH_1–3`) and writes every statement about qualification or indemnity into a fixed CSV: memo ID, supplier as written, topic, part family, position, exact quotation. Each batch must list back the memo IDs it read (sweep log). **Step C, page (code):** the page checks that every quotation appears word for word in the memo it cites and rejects any that doesn't. Memos with no extracted rows are shown in the coverage record, so a skipped memo is visible. **Step D, page (code):** applies §3 coverage, §4 flags with the BHD 50,000 threshold, §5 newest memo governs (showing both quotations with dates) and §6 status. **New memo intake:** load the new memo file plus its extraction rows; the page reruns everything and shows NOT STATED where the memo is silent. **People:** a second member re-checks a sample of the extraction in a fresh chat; the director and buyers decide what to do about any risk. **Why:** the rules are fixed logic, so code applies them the same way every run and anyone can read the code against the rule card. AI is used only where it helps, reading free text, and the quotation check stops it from inventing evidence. **Deliberately not used:** any API, any paid service, AI deciding flags or status, internet access. |
| 7 | **The trap we will demonstrate** | Week 7: we expect problems where RR-C5 is strict. We will look at supplier names in memos that differ from the master (§2), memos that mention a second supplier, memos that say an assessment is planned (§4.1), older and newer memos that disagree (§5) and vague contract wording such as "standard terms" (§4.3). Week 8: *(the one we found, with evidence)* |
| 8 | The refusal or limit we will show | A memo whose supplier name fails §2 matching is shown as CANNOT DETERMINE (match) and is not attached to any supplier. A quotation that isn't word for word in its memo is refused by the page. |
| 9 | **Where the human is** | The tool only shows risk. The category director and buyers decide what to do: find a second source, renegotiate an indemnity cap, schedule an assessment or accept the risk. The tool must not make these decisions because they involve cost, contracts and supplier relationships the pack doesn't cover, and it never changes a supplier's approval status. |
| 10 | How we will know it works | Expected results are written in `C5_TEST_RECORD` with their RR-C5 clause before every run. The coverage table is checked against all 26 suppliers in Excel. A second member traces at least five flags from quotation to memo in a fresh chat. After every change we rerun the regression cases. |
