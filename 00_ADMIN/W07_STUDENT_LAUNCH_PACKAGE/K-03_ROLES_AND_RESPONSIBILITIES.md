# K-03 — Roles and responsibilities

Five light roles — **responsibility anchors, not boundaries**.

| Role | Anchors | Never alone responsible for |
|-------------------|------------------------------------|----------------------|
| **Data / input lead** | pack integrity (inventory and fingerprints); source-of-truth questions | the group's understanding of the data |
| **Workflow / build lead** | the prototype's working files and versions, whatever form it takes (prompts, a Skill, a workbook, a web page, code) | the only working copy, or the only person who can explain how it works |
| **Tester** | the test record; expected before observed; regression | all the testing |
| **Evidence / documentation lead** | evidence folder, version notes, chat exports, checkpoint sheets | all the evidence |
| **Presenter** | run of show, timing, demo insurance, six-question answers | the only person able to run the demo |

**Rules**
- Every member runs **at least one core step in their own account** and authors **at least one extension case**.
- Every member can explain the whole project and run the core demonstration.
- Each role names a **cover** for absences.
- Roles may rotate at a checkpoint; write the change below.

## How to assign roles in 15 minutes
1. Each member says, in one sentence, which part of the brief they feel most and least confident about.
2. Fill the five roles; nobody takes two roles unless the group is smaller than five.
3. Name a **cover** for every role — a different member.
4. Each member writes the **core step they will run in their own account** (the "My core step" column).
5. The evidence lead starts the usage-budget card (K-07).

**Group size (guidance only):** three members → data + evidence, build + presenter, tester · four → data and evidence combined · five → one role each · six → a second tester ("trap hunter") or a split build role.
